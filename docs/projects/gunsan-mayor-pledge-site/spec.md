## 1. 프로젝트 개요

### 1.1 목적

군산시장 후보의 공약·정책·일정·소식을 시민이 *쉽게 이해하고 공정하게 비교*할 수 있도록 디지털 채널을 구축한다. 후보·캠프 입장에서는 공약 일관성·답변 신뢰성·법규 준수를 시스템적으로 담보하고, 시민 입장에서는 *공약 이행 추적 가능성*을 보장한다.

### 1.2 사업 범위 (In scope)

| 영역 | 포함 |
|------|------|
| 콘텐츠 | 후보 소개, 공약(분야별), 공약 이행 로드맵, 보도자료, Q&A, 자원봉사, 후원 안내 |
| 채널 | PC·모바일 반응형 웹, 다국어(국·영·중·일·베) — 군산 외국인 거주민 8% 고려 |
| 운영 | 캠프 측 콘텐츠 관리(CMS), 댓글·게시글 모더레이션, 신고 처리 |
| 보안 | 실명 인증(공직선거법 §82-7), HTTPS, WAF, 로그 보존 |
| 분석 | 공약별 조회수·체류시간, 지역구별 관심도(개인정보 비식별 집계) |
| 회계 | 후원금 약정·결제(외부 PG 연동), 기부 영수증 PDF 발급 |

### 1.3 사업 범위 외 (Out of scope)

- 후보 검증·팩트체크 자동화 (외부 언론·중앙선관위 자료 *링크*만)
- 타 후보 비교(공직선거법 §251 후보자 비방 금지 — 의도적 제외)
- 결제·은행 시스템 자체 운영 (제3자 PG/은행 위탁)
- 오프라인 행사 모객·티켓팅 (별도 시스템)

### 1.4 성공 지표 (KPI)

| 지표 | 목표 (선거일 기준 D-90 ~ D-1) |
|------|------------------------------|
| 누적 순방문자 | 군산시 인구의 30% 이상 (약 8만 UV) |
| 공약 페이지 평균 체류 | 60초 이상 |
| 자원봉사 신청 완료율 | 폼 진입 대비 40% 이상 |
| 후원 결제 성공률 | 95% 이상 (PG 표준) |
| 사이트 가용성 (SLA) | 월 99.9% |
| 웹 접근성 준수율 | KWCAG 2.2 AA 100% |

## 2. 시스템 아키텍처 개요

```
[시민/방문자]                     [후보 캠프 운영자]                [감사·외부]
      │                                      │                              │
      ▼                                      ▼                              │
┌──────────────────┐  ┌──────────────────────────────────┐                  │
│  공개 웹 (Next.js)│  │  CMS 어드민 (역할 기반 RBAC)     │                  │
│  반응형 PC/모바일 │  │  콘텐츠 워크플로 (초안→검수→발행)│                  │
└─────────┬────────┘  └────────────────┬─────────────────┘                  │
          │                            │                                    │
          ▼                            ▼                                    │
   ┌────────────────────────────────────────────┐         ┌──────────────────────┐
   │  API Gateway (NestJS) — JWT, Rate-limit    │◀────────│  중앙선관위 자료 링크│
   │  Audit log (immutable, 영구 보존)          │         └──────────────────────┘
   └────────┬──────────┬──────────┬─────────────┘
            │          │          │
       ┌────▼────┐ ┌───▼───┐ ┌────▼─────┐  ┌──────────────┐
       │PostgreSQL│ │ S3-호│ │ Redis   │  │ 외부 PG/PASS │
       │ (RLS)   │ │환 객체│ │ Cache  │◀─│ 실명인증·결제 │
       └─────────┘ └───────┘ └─────────┘  └──────────────┘
```

핵심 원칙:
- **실명 인증 게이트**: 글·댓글·신고는 공직선거법 §82-7에 따라 본인 확인 후 가능 (PASS·휴대폰·아이핀).
- **불변 감사 로그**: 모든 콘텐츠 발행·수정·삭제·신고 처리가 append-only 로그에 기록 (선거관리위원회 조회 대비).
- **수익·후원 분리**: 광고/콘텐츠와 후원금 흐름은 별도 테이블·별도 권한으로 격리 (정치자금법 회계 보고 자동화).
- **선거 종료 후 데이터 처리 정책**: 개인정보는 선거일+30일 자동 익명화, 후원 회계는 5년 보존 후 폐기.

## 3. 사용자 유형 (페르소나)

| ID | 유형 | 주된 행동 | 권한 |
|----|------|----------|------|
| P1 | 일반 시민 (비로그인) | 공약 열람, 공약 이행 로드맵 보기, 일정 확인, 보도자료 다운로드 | 읽기 전용 |
| P2 | 시민 (실명 인증 후) | Q&A 작성, 공약 의견 남기기, 신고, 자원봉사 신청, 후원 약정 | + 작성 |
| P3 | 외국인 거주자 | 다국어 공약·일정 열람 (국·영·중·일·베) | 읽기 전용 (실명 인증은 외국인 등록증 기반 별도 흐름) |
| P4 | 자원봉사자 (승인 후) | 일정 등록·수정 보조, 행사 사진 업로드 | 제한된 작성 |
| P5 | 캠프 콘텐츠 작성자 | 공약·보도자료 초안 작성·검수 요청 | 작성·수정 |
| P6 | 캠프 검수자 (선임 보좌관) | 공약 발행 승인, 댓글 모더레이션, 신고 처리 | 승인·삭제 |
| P7 | 캠프 회계 책임자 | 후원금 회계 조회, 정치자금법 보고서 출력 | 회계 전용 (콘텐츠 권한 없음) |
| P8 | 캠프 운영자(슈퍼관리자) | 권한 부여, 사이트 설정, 비상 차단 | 전체 |
| P9 | 외부 감사 (선관위·언론) | 공개 감사 로그 *해시 일부* 조회 (개인정보 비식별) | 읽기 (감사 전용 뷰) |
| P10 | AI 보조 작성자 | 공약 초안 다국어 번역 보조, 평이한 언어 변환 (인간 검수 필수) | 시스템 권한 (별도 토큰) |

권한 분리 원칙:
- **콘텐츠 권한 ≠ 회계 권한** — 한 사람이 두 권한을 동시에 가지지 않는다 (정치자금법 회계 책임 분리).
- **슈퍼관리자 작업은 2-of-N 승인** — 권한 변경·전체 콘텐츠 일괄 삭제 등은 두 명이 동의해야 실행.
- **AI 보조는 항상 인간 승인 후 발행** — AI provenance(모델·프롬프트 버전·생성 시각) 기록 필수.

## 6. 화면별 상세 기능 정의

각 화면 단위로 (입력 → 처리 → 출력 → 예외 → 인수 기준) 5요소를 명시한다.

### 6.1 홈 (랜딩) — `/`

| 요소 | 내용 |
|------|------|
| 화면 ID | SCR-HOME |
| 목적 | 첫 진입자에게 *후보 가치관 한 줄 + 핵심 공약 3개 + 다음 일정 1개*를 7초 안에 전달 |
| 입력 | (없음) |
| 처리 | CMS 발행 콘텐츠 캐시 → 레이아웃 조립 |
| 출력 | 히어로 슬로건, 핵심 공약 3 카드, 다음 일정 1 카드, 최근 보도자료 3건, CTA(자원봉사·후원·Q&A) |
| 예외 | 콘텐츠 미발행 시 *기본 안내문* 노출, 캐시 무효화 시 5초 내 재로드 |
| 인수 기준 | LCP < 2.5s, CLS < 0.1 (모바일 4G), 대체 텍스트 100% |

### 6.2 후보 소개 — `/about`

| 요소 | 내용 |
|------|------|
| 화면 ID | SCR-ABOUT |
| 입력 | (없음) |
| 처리 | 약력·이력·재산·병역·전과 데이터 → 표 렌더링 |
| 출력 | 약력 표, 비전 메시지, 의무공개 표(가족·재산·병역·전과), 다운로드 PDF |
| 예외 | 의무공개 항목 미입력 시 발행 차단 (CMS 검수 게이트) |
| 인수 기준 | 공직선거법 의무공개 항목 100% 표시, 출처(중앙선관위 후보등록 자료) 링크 |

### 6.3 공약 분야별 카드 — `/pledges`

| 요소 | 내용 |
|------|------|
| 화면 ID | SCR-PLEDGES |
| 입력 | 분야 필터(8개), 검색어(선택), 정렬(우선순위·예산순) |
| 처리 | DB 쿼리 → 분야별 카드 렌더 → 카드 클릭 시 상세 페이지로 라우팅 |
| 출력 | 카드 그리드 (제목·요약 1문장·분야 배지·예산 규모·이행 시기), 분야 필터 칩 |
| 예외 | 검색 결과 0건 시 *유사 분야 제안* |
| 인수 기준 | 모든 카드에 *재원 출처 1줄* 노출 (재원 미명시 카드는 발행 불가) |

### 6.4 공약 상세 — `/pledges/[id]`

| 요소 | 내용 |

| 화면 ID | SCR-PLEDGE-DETAIL |

| 처리 | 본문·KPI·재원·이행 일정 렌더 → 댓글 비동기 로드 → 신고 버튼 활성화 |
| 출력 | 본문, KPI 표, 예산·재원, 이행 단계(단·중·장기), 인용 출처, 의견 댓글, 공유 버튼 |

| 인수 기준 | 모든 사실 단정에 *출처 링크* (출처 0건 시 발행 차단), 평이한 언어 점수 ≥ 60 |

## 7. 데이터 모델 개요

핵심 엔티티 (Prisma/SQL 기준 — 컬럼명은 snake_case로 가정).

### 7.1 사용자·권한

```
users
  id (uuid PK)
  display_name
  email_hash         (해시만 저장 — 원문은 별도 KMS)
  phone_hash
  identity_verified  (bool — 실명 인증 완료 여부)
  identity_verified_at
  identity_provider  ('PASS' | 'phone' | 'ipin' | 'foreigner')
  status             ('active' | 'suspended' | 'deleted')
  created_at, updated_at

roles
  id, key            ('super_admin' | 'editor' | 'reviewer' | 'accountant' | 'volunteer_lead' | 'volunteer' | 'reader')
  name

memberships
  user_id, role_id, granted_by, granted_at
  unique (user_id, role_id)
```

회계와 콘텐츠 권한은 *동시 보유 금지* — 애플리케이션 레이어에서 `accountant + editor` 조합 거부.

### 7.2 콘텐츠

```
pledges
  id, slug, sector ('saemangeum'|'youth'|...|'welfare'),
  title_i18n, summary_i18n, body_i18n,    -- JSONB, 5개 locale
  budget_amount, budget_source,            -- 재원 출처는 자유 텍스트 + 출처 URL 1건 이상
  timeline_phase ('100d' | '2yr' | 'long'),
  kpi (JSONB),
  citations (JSONB array of {label, url, accessed_at}),
  state ('draft'|'review'|'published'|'retired'),
  ai_provenance (JSONB | null),
  published_at, published_by,
  retired_at, retire_reason
  created_at, updated_at

pledge_revisions
  id, pledge_id, snapshot (JSONB), diff (JSONB), changed_by, changed_at
  -- append-only — 발행 후 수정 시 매 변경마다 한 행

press_releases
  id, title, body, attached_pdf_url, video_embed_url,
  state, published_at, published_by, ...

cards          -- 카드뉴스
proposals      -- 시민 제안
qna_threads, qna_replies
schedule_events
  id, title, location, starts_at, ends_at, capacity, rsvp_count, public

volunteer_apps
  id, user_id, areas[], available_slots, terms_agreed_at,
  consent_record (JSONB),  -- 동의 시점·텍스트 해시
  status ('pending'|'approved'|'rejected'|'withdrawn'),
  expires_at  -- 선거일 + 30일
```

다국어 `*_i18n` 필드는 `{ ko: { ... }, en: { ... }, zh: { ... }, ja: { ... }, vi: { ... } }` 구조. ko 미입력 콘텐츠는 발행 차단.

### 7.3 상호작용·신고

```
comments          -- 공약 의견·정책 제안 답글
  id, parent_type ('pledge'|'press'|'card'|'qna'|'proposal'),
  parent_id, author_user_id (FK users),
  body, state ('queue'|'visible'|'hidden'|'deleted'),
  hidden_reason, ...

reports
  id, target_type, target_id, reporter_user_id,
  reason ('false_info'|'defamation'|'harassment'|'spam'|'other'),
  body,
  status ('open'|'in_review'|'resolved'|'rejected'),
  resolved_by, resolved_at, resolution_note,
  created_at
```

### 7.4 후원·회계 (격리 스키마 권장)

```
donations
  id, donor_user_id, amount, currency ('KRW'),
  pg_provider, pg_transaction_id, pg_status,
  pledged_at, charged_at, refunded_at,
  receipt_id, donor_name_hash, donor_resident_no_hash,
  audit_lock (bool — 회계 보고 후 수정 잠금)

receipts
  id, donation_id, pdf_url, issued_at, sequence_no
  -- 정치자금법 §40 항목

expenses
  id, category, amount, vendor, paid_at, evidence_url, ...

quarterly_reports
  id, quarter, total_donations, total_expenses, donor_count,
  cohort_aggregates (JSONB — k≥10),
  filed_at, filed_by, official_form_pdf
```

회계 테이블은 *별도 DB 스키마*에 두고, 회계자 외에는 SELECT 권한 없음. 분기 보고 후 `audit_lock=true`로 수정 잠금.

### 7.5 감사 로그 (불변)

```
audit_events
  id, actor_user_id, action,
  resource_type, resource_id,
  before (JSONB), after (JSONB),
  ip_hash, user_agent_hash,
  occurred_at
  -- DB trigger: UPDATE/DELETE 거부 (append-only)
```

선거관리위원회·언론 감사 시 `action`·`resource_type`·`occurred_at` 일부만 노출하는 별도 뷰 제공.

| 동시 접속 (선거 마지막 주) | 5,000 RPS, 50K 동시 사용자 처리 |
| 캐시 적중률 (CDN) | > 90% |

### 8.2 가용성·신뢰성

- 월 가용성 99.9% (다운타임 월 약 43분 이하)
- 다중 가용존(AZ) 배포, RDS 자동 페일오버
- 백업: 일일 스냅샷 + 시간별 WAL, 30일 보존
- DR: 다른 리전 standby, RPO 15분, RTO 1시간

### 8.3 보안

- 모든 통신 HTTPS (TLS 1.3, HSTS)
- WAF: SQL injection, XSS, CSRF, OWASP Top 10
- DDoS 보호 (CDN/Cloudflare 또는 AWS Shield)
- 비밀: KMS 관리, 환경 변수 평문 저장 금지
- 비밀번호: Argon2id (메모리 64MB, 반복 3, 병렬 4)
- 캠프 직원 2FA 의무 (TOTP/WebAuthn)
- 정기 침투 테스트 (오픈 1주 전 + 월 1회)

### 8.4 접근성

- KWCAG 2.2 AA 100%
- 화면 낭독기 (NVDA, JAWS, VoiceOver) 100% 탐색 가능
- 키보드만으로 모든 기능 사용 가능
- 색맹 대비 (4.5:1 대비비)
- 동영상 자막 의무, 이미지 alt-text 의무

### 8.5 개인정보·데이터 보호

- 개인정보 수집 *최소화 원칙* — 자원봉사·후원·실명 인증 시 *목적별 분리 동의*
- 보존 기간:
  - 자원봉사 신청 정보: 선거일 + 30일 → 익명화
  - Q&A·신고 작성자 정보: 선거일 + 90일 → 익명화 (단 신고는 5년 보존)
  - 후원 회계: 5년 보존 후 폐기 (정치자금법)
- 암호화: 민감 식별 정보 AES-256 (필드 단위), 백업 암호화
- 익명화: 이름·연락처·주민번호 hashed/salted, 평문 미보존
- 제3자 제공 금지 (단 법령상 의무 제외)

### 8.6 다국어·접근 형평성

- 5개 언어: ko (기본) / en / zh / ja / vi
- 외국인 거주민 대상 별도 인증 트랙 (외국인 등록증)
- 평이한 언어 점수 ≥ 60 (한국어 원문 기준)
- AI 보조 번역 → 인간 검수 (provenance 기록)

### 8.7 SEO·소셜

- OG/Twitter Card 메타 자동 생성
- 구조화 데이터 (Schema.org `Person`, `Event`)
- sitemap.xml, robots.txt
- 카카오톡 공유 미리보기 최적화 (썸네일 800x418)

## 10. 운영·유지보수

### 10.1 콘텐츠 운영 절차

```
[작성자] 초안 작성
   ↓
[검수자] 평이한 언어 / 사실 출처 / 인용 / 비방 키워드 검토
   ↓
[승인자(선임)] 발행 승인
   ↓
[시스템] 발행 + 감사 로그 기록 + CDN 캐시 무효화 + SNS 자동 공유 (선택)
```

- SLA: 작성 → 발행 평균 4시간, 긴급(보도자료) 1시간
- 야간·휴일 당직 1인 배정 (선거 D-30 ~ D-1)
- 캠프 채널(Slack 또는 카카오워크)에 발행 알림 자동 게시

### 10.2 사고 대응 (Incident response)

- **레벨 1 (서비스 중단)**: 5분 내 1차 응답, 1시간 내 복구
- **레벨 2 (보안 사고)**: 30분 내 슈퍼관리자 알림, 즉시 KISA 신고
- **레벨 3 (콘텐츠 사고: 허위·비방·법규 위반)**: 1시간 내 비공개 처리 + 검수 회의 + 24시간 내 결과 공지
- **레벨 4 (회계 의심)**: 즉시 회계 책임자·법률 자문 호출, 외부 감사 협조

### 10.3 모니터링·알림

- 가용성: Pingdom 또는 UptimeRobot 1분 간격
- 성능: Web Vitals 일일 보고
- 에러: Sentry — 캠프 슈퍼관리자에게 알림
- 보안: WAF 차단 로그 일일 요약 → 슈퍼관리자 이메일

### 10.4 백업·복구

- DB 일일 스냅샷 + 시간별 WAL
- 객체 스토리지 버전 관리 (S3 versioning)
- 분기별 *복구 훈련* — DR 환경에서 전체 복구 실행 후 RTO/RPO 측정
- 선거 종료 후 1년간 모든 백업 보관 (선관위 감사 대비)

### 10.5 종료·해체 (Decommission)

- 선거일 + 30일: 자원봉사·시민 게시 데이터 익명화
- 선거일 + 90일: 활성 운영 종료, 정적 아카이브 사이트로 전환
- 선거일 + 5년: 정치자금 회계 데이터 폐기
- 종료 절차는 별도 *해체 계획서*에 명시 (별도 문서)
