# 칼럼 시나리오 컨셉 — SDG 임팩트 분석 칼럼

> 본 플랫폼 `Column` 도메인(ADR-0013) 발행 트랙 = `external` 또는 `internal`
> 12-rule integrity verifier(`ColumnService.eligibilityErrors` + `verifyIntegrity`) 자동 통과 가능한 시나리오 양식.
> 참고 모델: SERICEO People Insight (코스트코/무신사 등 비즈니스 전략 분석 칼럼).

## 1. 왜 SERICEO 양식을 참고하는가

업로드된 두 칼럼(무신사 IP 비즈니스 / 코스트코 직원 중심 문화)을 분해하면 *공통 골격*이 분명하다:

| 구성 요소 | SERICEO 양식 | 본 플랫폼 적용 |
|-----------|-------------|--------------|
| **1줄 후크** | "92% 갱신율의 비밀" | "혈중 칼륨 30% 낮춘 마을의 비결" |
| **놀라운 숫자** | 코스트코 직원 1인당 매출 $79만 (월마트 $32만) | LDC NGO 1명이 6개월에 정수기 800대 보급 |
| **반직관** | "비용절감 시대에도 직원 의료비를 늘렸다" | "전기 없는 지역에서 더 정확한 데이터가 나왔다" |
| **CEO 또는 실무자 인용** | "좋은 사람을 고용하면 반드시 좋은 일이 일어난다" — 짐 시네갈 | "K 농도를 떨어뜨리니 잎이 더 맛있어졌다" — 현장 영양관리자 |
| **비교표** | 코스트코 vs 월마트 생산성 | 무동력 시설 vs 식물공장 KWh/kg |
| **결론은 질문으로** | "우리 조직은 직원을 비용으로 보는가, 경쟁력의 원천으로 보는가?" | "당신 지역의 SDG는 비용으로 측정되고 있나, 사람으로 측정되고 있나?" |

본 플랫폼이 매일 발행하는 칼럼이 이 *5중 골격*을 갖추면 — 8,000자 분석 보고서가 아니라도 — 독자가 *"한 번 더 생각하게 되는"* 효과를 일관되게 낼 수 있다.

## 2. 본 플랫폼만의 추가 의무 (ADR-0013 § 12-rule)

SERICEO와 다른 본 플랫폼만의 *비-타협 규칙*:

1. **모든 사실 단정은 1차 자료 인용** — `sourceUrl` 필수, 인용 0건이면 발행 차단 (ADR-0013).
2. **트랙 구분 표시** — `origin = 'external'`(외부 큐레이션) 또는 `'internal'`(자체 발행) 명시 (ADR-0014 §4).
3. **평이한 언어** — 영어 + 한국어 두 언어 본문. plain-language 점수 ≥ 60 (ADR-0011).
4. **SDG 매핑** — `sdgFocus[]`에 해당 SDG 코드 1개 이상 + AI 매핑 신뢰도 < 0.70이면 인간 확정 필수.
5. **민감 주제 2인 승인** — 의료·법·갈등·아동 관련은 `sensitivity = 'sensitive'`로 표시 → 검토자 2명 필요 (ADR-0013).
6. **해로운 콘텐츠 가드 통과** — `checkHarmfulContent()` 자동 적용 (ADR-0016).
7. **AI 보조 시 provenance** — `aiProvenance: { model, promptVersion, draftedAt }` 필수.
8. **승인 게이트** — 발행 전 인간 ≥ 1명 (민감은 ≥ 2명) HMAC 토큰 단일 사용 승인 (ADR-0013 §3).

## 3. 칼럼 4가지 시나리오 유형

본 플랫폼이 매일 1편 발행할 칼럼을 **4가지 유형**으로 분류한다. 한 주에 각 유형이 한두 편씩 — 독자에게 리듬을 준다.

| 유형 | 빈도 | 길이 | 톤 (ADR-0016) | 후크 양식 |
|------|------|------|--------------|-----------|
| **A. 사례 분석** (Case study) | 주 2편 | 800~1,200자 | `instructive` | "X 마을은 어떻게 Y를 했는가" |
| **B. 데이터 한 컷** (Data snapshot) | 주 1편 | 500~700자 | `solemn` 또는 `reflective` | "숫자 한 줄: Z 지역의 어제와 오늘" |
| **C. 발견 큐레이션** (Watch curation) | 주 2편 | 400~600자 | `friend` | "이번 주 발견된 3가지" |
| **D. 실천가 인터뷰** (Practitioner Q&A) | 주 1편 | 1,000~1,500자 | `friend` 또는 `reflective` | "현장의 목소리: ABC가 묻습니다" |
| **E. 역사·맥락** (Historical lesson) | 격주 1편 | 1,200~1,800자 | `instructive` 또는 `reflective` | "X의 발견까지 184년이 걸렸다" |

각 유형은 `Column.bodyI18n` 의 `title`·`summary`·`excerpt` 슬롯에 그대로 매핑된다. excerpt는 250 단어 이하 (ADR-0013 §1).

### 3.1 Type E의 추가 분석 — 천연고무 칼럼에서 추출

업로드된 *천연고무의 인기* 칼럼을 분해하면, 사례 분석(Type A)과 *명백히 다른* 골격이 드러난다:

| 차이점 | Type A (사례 분석) | Type E (역사·맥락) |
|--------|-------------------|-------------------|
| 시간축 | 단일 시점·단일 케이스 | 장기 시간축(수십~수백 년), 여러 사건 연결 |
| 인물 밀도 | 1~2명 깊이 인용 | 다수 인물·연도 *나열* (콜럼버스→굿이어→루즈벨트) |
| 닫는 방식 | 독자에게 *질문* | 일반화된 *교훈* (선언형) |
| 신뢰 형성 | 현장 데이터·수치 | 날짜·고유명사의 *축적* |
| 길이 | 800~1,200자 | 1,200~1,800자 |
| 평행 구조 | 비교 표 (X vs Y) | 사건 비교 ("맨해튼 프로젝트와 더불어…") |

**왜 Type E가 SDG 칼럼에 중요한가:**

1. *변화가 가능함을 증명* — 천연두 박멸 184년, ORS 50+ 백만 생명 구원, 인도 백색 혁명 등 SDG와 직접 연결되는 장기 성공 사례가 풍부.
2. *회의론자에게 더 설득력* — 현재의 데이터는 의심받지만 역사적 증거는 반박이 어렵다.
3. *"우리는 긴 이야기의 한 페이지" 정체성* — 실천가에게 *지속할 동기*를 부여 (Type A는 *시작할 동기*).
4. *선택과 집중·산·관·학 협력* 같은 일반화 가능한 패턴을 사례에서 추출 — 다음 ImpactStudy(ADR-0017)·BizPlan(ADR-0019) 작성자의 사고 도구가 된다.

**Type E의 주의 사항:**

- 역사적 인물·국가 묘사에서 *현재의 가치*를 과거에 투영하지 않기.
- 식민지·전쟁기 사례는 *피해자 관점*도 함께 배치 (ex: 천연고무 강제 노동 — 콩고 자유국).
- 본 플랫폼 12-rule §3의 *사실 단정 금지*가 역사 서술에서도 똑같이 — "X가 발명했다"보다 "X가 처음 출원했다"처럼.
- 본 플랫폼 1차 자료가 빈약한 영역(먼 과거)이라도 외부 인용은 학술 출판 + DOI 우선.

## 4. 공통 5중 골격 — 한 편의 칼럼 안에서

SERICEO에서 추출해 본 플랫폼 의무에 정렬한 *모든 칼럼이 따라야 하는 흐름*:

```
[1] 후크 (1~2문장)
   숫자 한 개 + 반직관 한 가지. 첫 문장에 "왜?"를 심는다.
   예: "전기를 거의 쓰지 않는 농장이 식물공장보다 정확한 칼륨 데이터를 냈다."
   
[2] 배경 (2~3문장)
   왜 이 이야기가 *지금* 중요한가. 어느 SDG·어느 지역·어느 사람.
   본문 안에 sdgFocus와 region이 *말로* 등장해야 한다.
   
[3] 본문 (3~4문단, 각 문단에 인용 1건 이상)
   - 사실 → 출처 → 해석 → 비교의 4박자.
   - 가급적 표 1개 또는 콜아웃 1개로 시각 휴식.
   - "Smith et al., 2025" 같은 외부 인용은 DOI/PMC URL 필수.
   - 본 플랫폼 1차 자료 인용(Watch §X / Column §Y / Manuscript §Z) 우선.

[4] 인용·증거 박스
   - 출처 표 (제목 / 저자 / 발행일 / URL / 라이선스)
   - 본문에서 인용한 모든 항목이 여기서 한눈에 추적된다.
   
[5] 결론은 질문으로
   "X는 무엇을 의미하는가?" 가 아니라 "당신의 Y는 어떤가?" 로 닫는다.
   독자가 *행동*으로 옮길 1줄 cue (예: "당신 지역의 보건소 K 측정 빈도는?")
```

길이 제어: A 유형은 [1]–[5] 전부 포함 1,000자 안쪽. C 유형은 [1] + [3] 축약본 + [4]만으로 500자.

## 5. 톤 안내 (ADR-0016 5톤 라이브러리 매핑)

같은 사실도 어떤 톤으로 말하느냐가 독자 행동을 좌우한다.

| 상황 | 추천 톤 | 클로징 시그니처 |
|------|--------|----------------|
| 가벼운 발견·일상 SDG 행동 | `playful` | "오늘 한 번, 내일도 한 번" |
| 또래 실천가에게 권유 | `friend` | "있잖아, 우리도 한번 해볼래?" |
| 아동·재난·갈등 | `solemn` | "오늘의 한 줄, 내일의 세상" |
| 새 기술·새 사실 | `instructive` | "알아두면 달라지는 한 가지" |
| 자기성찰·정체성 | `reflective` | "잠시 멈추어, 우리는 무엇을 만드나" |

원칙: 같은 칼럼 안에서 톤이 흔들리지 않는다. 한 편 한 톤. 시그니처 클로징은 ADR-0016 §A.1의 `closingFor(tone, locale)` 함수가 자동 생성.

## 6. 금지 — 본 플랫폼이 절대 쓰지 않는 표현

| 금지 | 이유 | 대안 |
|------|------|------|
| "혁명적인" / "대박" / "초대박" | 과장. 독자 신뢰 훼손. | "측정 가능한" / "n배 개선된" + 출처 |
| "전문가들은 말한다" (출처 무) | 익명 권위 호소 | 실명 + 소속 + 인용 일자 |
| "당연히" / "분명히" | 사실 점프 | "X 데이터에 따르면…" |
| 부정확한 일반화 ("아프리카는 전부…") | 지역·문화 평탄화 | 국가·지역 단위로 좁힘 |
| 비교 우위 자랑 ("우리만이…") | 비영리 정신 위배 | 협력 가능성 강조 |
| 환자·취약 계층의 *동의 없는* 사연 | ADR-0017 consent 위반 | 익명화 + 동의 근거 명시 |

## 7. AI 보조 시 표시 규칙 (ADR-0019 § AI provenance)

칼럼 본문에 AI가 작성에 참여한 경우:

- 본문 끝에 *작은 글씨*로 다음 한 줄을 자동 부착:
  > "이 글은 `claude-opus-4-7` (프롬프트 v3.2)로 초안 작성, 2026-04-26 인간 검토자 OO 승인."
- `aiProvenance` 필드에 동일 정보 영구 기록.
- AI가 *인용 없이 사실 단정*하면 자동 차단 (ADR-0019 §A.2).

### 시나리오 ① 사례 분석 (Type A) — 톤 `instructive`

**제목 (ko/en)**:
- 한국어: "전기 없이 더 정확했다 — 다카 외곽 마을의 저칼륨 채소 12주 데이터"

**SDG 매핑**: SDG-3, SDG-6, SDG-7 / region: BD / sensitivity: `sensitive` (의료) → 검토자 2명 필요

**5중 골격**:

```

[4] 인용 박스

### 시나리오 ② 데이터 한 컷 (Type B) — 톤 `solemn`

**제목**:
- 한국어: "숫자 한 줄 — 시범 마을의 어제와 오늘, 그리고 빠진 한 사람"
- English: "One line of data — yesterday, today, and the person who's missing"

**SDG 매핑**: SDG-3, SDG-6 / region: TZ / sensitivity: `sensitive`

**5중 골격 (단축본 — 600자 이내)**:

```
[1] 후크
"한 줄. 탄자니아 도도마의 마을 보건소 등록 CKD 환자: 어제 47명, 오늘 46명."

[2] 배경
 한 명이 빠졌다. 이송이 늦었다. 통계의 -1은 한 사람의 100%다.

[3] 본문 (1문단)
 우리 플랫폼이 측정한다고 해서 사람이 살아 돌아오지 않는다.
 그러나 측정하지 않으면 *왜 빠졌는지*도 모른다.
 데이터는 우리가 그 사람을 *기억하기 위한 마지막 약속*이다.
 (cohort k=46 < 25 floor 통과 — 마을 단위 공개 가능)

## 9. 발행 워크플로 매핑

세 시나리오 모두 본 플랫폼 `Column` 상태 머신을 그대로 탄다 (ADR-0013):

```
draft (작성자)
  → pending (eligibilityErrors 없음 + 12-rule 통과 + 해로운 콘텐츠 가드 통과)
    → ApprovalRequest 발급 (HMAC 토큰, 72h, 단일 사용)
      → published (n-of-m 승인 도달; sensitive면 n=2)
        → Atom feed (CC BY 4.0) + 파트너 webhook (HMAC-SHA256) + 다국어 카드뉴스 자동 변환
```

발행 후:
- `Column` → 1차 자료로서 다른 BizPlan(ADR-0019), Manuscript(ADR-0017)에 인용 가능.
- 시나리오 ①처럼 ImpactStudy를 인용한 칼럼은, 그 ImpactStudy가 retire되면 *주의 배지* 자동 부착 (ADR-0017 §C.4).
